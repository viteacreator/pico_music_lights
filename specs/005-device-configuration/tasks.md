# Feature 005 — Ordered Implementation Tasks

No task is implemented by this specification package. Every implementation task must leave the repository compilable, must not add Wi-Fi/web/JSON/OTA/USB configuration protocol scope, and must preserve Features 001–004 except where an approved task explicitly integrates loaded configuration.

1. Public configuration types and fixed limits. Scope: add `config/device_config.*` with fixed limits, LED/effect/Idle/audio calibration value types, result enums, eight-channel persistent capacity (`kMaximumLedChannelCount = 8`), board-supported channel-count capability, physical metadata semantics (`length_mm == 0` unknown, density 0 unknown and 1..1000 known), no persisted GPIO field, and static assertions separating persistent capacity from current board/effect runtime capacity. Likely files: new `include/config/`, `src/config/`, host CMake. Tests: compile-only and field-limit host tests. Completion: Pico and host builds compile. Dependencies: none.

2. Canonical Gyver audio-calibration ownership. Scope: make `AudioCalibrationConfig` the only canonical owner for Gyver VU/spectrum calibration, define adapters that overlay global calibration into runtime `StripEffectConfig` mirrors, and define normalization for active/draft reads. Likely files: new `config` adapter modules and host tests. Tests: canonical ownership, runtime overlay, read normalization, dirty/equality ignoring mirror fields, and contradictory mirror values rejected or normalized before persistence. Completion: no persisted API exposes per-channel contradictory Gyver calibration. Dependencies: task 1.

3. Factory defaults and physical metadata defaults. Scope: add factory construction for eight persistent channels: channels 0..5 enabled with current GP2–GP7 board mapping, 132/174/141/81/96/72 pixels, GRBW, unreversed, brightness 16, density 60, length 0 mm unknown, and Gyver VU defaults; channels 6..7 disabled with zero pixels, Effect Off, brightness 16, unreversed, unknown length, unknown density, and no stored GPIO. Tests: host assertions for every default field, current six-channel hardware defaults, reserved-channel defaults, known and unknown millimetre metadata, and global-only calibration defaults. Completion: defaults match requirements and no startup behavior changes. Dependencies: tasks 1–2.

4. Configuration validation. Scope: implement whole-config and preview-subset validation for fixed eight-channel capacity, current board-supported channels, unsupported channels disabled, enabled nonzero pixel counts, disabled-channel retained counts, board/runtime total-pixel capability using `uint32_t`, brightness/order enums, optional metadata ranges, absence of persisted GPIO, effects with calibration mirrors excluded, Idle masks limited to board-supported channels, canonical audio floors, and overflow. Tests: positive, boundary, malicious-field, invalid enum/source/pixel/unsupported-channel/forbidden-GPIO/Idle/audio/metadata cases. Completion: all invalid cases return typed diagnostics without side effects. Dependencies: tasks 1–3.

5. Draft, active, and persisted state management. Scope: add `ConfigService` state ownership, dirty tracking, reload/discard, normalized active/draft reads, and all-or-nothing publication stubs that initially use factory defaults. Tests: state-transition host tests and prevention of contradictory calibration state. Completion: service compiles and preserves current runtime until later integration tasks. Dependencies: task 4.

6. Explicit serialization and deserialization. Scope: add deterministic little-endian schema-1 codec with fixed buffers and stable enum ids, exactly eight LED-channel records, exactly eight effect records, no GPIO fields, `uint16_t length_mm`, `uint16_t density_pixels_per_metre`, per-channel `uint16_t pixel_count`, board total-pixel capability outside the schema, duplicated Gyver calibration mirror fields excluded from effect records, and global calibration serialized exactly once. Tests: round trip, known byte order, eight-record payload lengths, no serialized GPIO, serialization without duplicated calibration values, canonical calibration round trips, known/unknown millimetre metadata, truncation, length mismatch, malformed bool/enum, integer-overflow safety. Completion: no raw struct-memory persistence, no duplicated calibration payload, no persisted GPIO, and no schema dependence on current total-pixel capability. Dependencies: task 4.

7. CRC32. Scope: add standalone CRC32 implementation. Tests: known vectors, incremental vs one-shot, empty payload. Completion: usable by codec/record tests. Dependencies: none.

8. Slot format and slot inspection. Scope: define header, commit marker, payload/header CRC checks, erase-state handling, and per-slot diagnostic summary. Tests: valid slot, erased, bad magic, bad commit, partial commit marker, illegal marker transition, bad header CRC, bad payload CRC, bad length, unsupported schema. Completion: host inspection classifies every case. Dependencies: tasks 6–7.

9. Newest-valid-slot selection and sequence ambiguity. Scope: implement two-slot selection, ordinary half-range sequence comparison, duplicate equality handling, exact `0x80000000` ambiguity handling, diagnostics, and deterministic selected slot. Tests: one invalid/one valid, both invalid, both valid A newer, B newer, duplicate sequence selects A, wrap `0xFFFFFFFF -> 0`, exact half-range ambiguity selects A and emits `sequence_ambiguous`. Completion: selected source and fallback reason are deterministic. Dependencies: task 8.

10. Deterministic write-target selection. Scope: implement target choice without erasing the selected valid slot: other slot when one selected slot exists, non-selected slot when both are valid, slot B for duplicate/ambiguous A-selected cases, and slot A with initial sequence 0 when neither slot is valid. Tests: target selection, selected-slot preservation, initial save, alternating slots, sequence wrap next value, both invalid first write. Completion: old selected slot remains untouched before final verification. Dependencies: task 9.

11. Interrupted and corrupt write handling model. Scope: specify and implement write transaction state machine independent of hardware backend, including readback/decode/CRC/validation before authority changes and factory reset through the same transaction. Tests: interrupted erase, interrupted program before payload complete, interrupted commit marker, corrupt padding, previous valid recovery, write failure, readback failure, reset failure. Completion: fake transactions prove new slot is not authoritative until committed and verified. Dependencies: tasks 8–10.

12. Flash backend abstraction. Scope: add read/erase/program/bounds interface with alignment, region descriptors, and operation counters for proving no pre-safe-point writes. Tests: fake backend rejects misalignment/out-of-range and records operations. Completion: storage code depends only on abstraction. Dependencies: task 11.

13. Host fake-flash backend. Scope: implement erase-state array, programmable 1-to-0 semantics, injected failures and interruption points. Tests: corruption and power-interruption simulations. Completion: all storage edge tests run without Pico SDK. Dependencies: task 12.

14. Device configuration store. Scope: combine codec, records, selection, target choice, fake backend writes, verification readback, and persisted-state update for the eight-channel schema. Tests: save/load positive, fallback to defaults, both slots invalid, unsupported schema, CRC/length mismatch, selected-slot preservation, alternating slots, readback failure, and future-compatible reserved-channel retention. Completion: host store is deterministic. Dependencies: tasks 6–13.

15. Persistent region layout checks. Scope: add compile-time constants and runtime validation hooks for flash size, sector alignment, slot placement, linker image end, and reserved areas, plus build/link-time reservation or size assertion. Tests: host runtime descriptor overlap/alignment cases and a build/link-time negative overlap verification that fails before a flashable artifact is produced. Completion: overlap is refused before slot access, the Pico build fails if the image would grow into the reserved region, and no intentionally overlapping image is flashed. Dependencies: task 12.

16. Pico SDK flash backend. Scope: implement RP2040 read/erase/program backend using SDK alignment, RAM-resident critical flash calls where required, and no real-time invocation. Tests: compile Pico Release; host remains unaffected. Completion: backend builds for Pico W and is not called from ISR/render paths. Dependencies: tasks 12 and 15.

17. Controlled runtime activation. Scope: publish previewable non-structural changes through EffectEngine/Idle/audio calibration at render/audio-safe boundaries, adapt only current board-supported channels to the six-channel runtime LED/effect layers, reject enabled unsupported channels, overlay canonical Gyver calibration into applicable runtime effect configs, and handle structural LED changes through two-phase reinitialization/restart boundary. Tests: atomic success/failure, runtime overlay, board-supported-only publication, unsupported-channel rejection, structural-not-mid-frame, partial reinitialization failure, dirty tracking. Completion: invalid publication leaves active config unchanged. Dependencies: task 5.

18. Bounded safe-point acquisition. Scope: add compile-time bounded LED-frame and audio-safe-point deadlines before flash operations, typed timeout diagnostics, state restoration, and operation-counter proof that no flash transaction was issued on timeout. Tests: permanently busy LED output, continuously pending audio work, timeout recovery, active/draft/persisted state unchanged, rendering/audio restored, wait-time diagnostics separated from flash critical-section time. Completion: Save aborts safely before erase/program on either timeout. Dependencies: tasks 12 and 17.

19. Controlled save integration. Scope: add save coordinator that uses controlled activation when needed, deterministic write-target selection, bounded safe-point acquisition, flash transaction, readback verification, runtime restoration, and duration/drop diagnostics. Tests: host coordinator simulation plus Pico build, including activation-success/write-failure dirty semantics, selected-slot preservation, alternating slots, sequence wrap, readback failure, and no flash operation before safe points. Completion: save can only be requested explicitly and all save failure phases match the design. Dependencies: tasks 14, 16, and 18.

20. Boot integration. Scope: normal startup loads newest valid supported config or factory defaults before renderer enable; validates the eight-record payload against current board capability; publishes only board-supported channels; diagnostic scenes do not auto-run in Release; active/draft reads normalize calibration mirrors. Tests: host boot policy and Pico build. Completion: current factory behavior is reproduced when slots are empty, with fallback diagnostics. Dependencies: tasks 14, 16, and 17.

21. Factory reset. Scope: explicit confirmation API, factory activation, reset through the same safe slot transaction, and reset diagnostics. Tests: wrong confirmation rejected, confirmed reset restores defaults, reset write failure/readback failure preserves previous selected slot and distinguishes active vs persisted state. Completion: no accidental reset path and no erase-both-slots reset behavior. Dependencies: tasks 19–20.

22. Bounded diagnostics. Scope: add fixed summary of boot source, slot states, target slot, duplicate/ambiguous sequence, dirty flag, active-vs-persisted status, validation error, save/reset status, safe-point wait durations, flash critical-section duration, dropped frames/audio interruption, schema, and flash bounds. Tests: formatting/bounds host tests if formatting is project-owned. Completion: Release diagnostics are bounded; development USB helpers disabled by default. Dependencies: tasks 18–21.

23. Focused host tests and suite registration. Scope: add or extend host suites for config validation, codec, storage, fake flash, service lifecycle, eight-channel schema compatibility, board/runtime capability separation, no persisted GPIO, canonical calibration ownership, millimetre physical metadata, target selection, sequence ambiguity, bounded safe points, and build-time overlap negative verification. Tests: run all registered host suites under GCC, Clang, GCC ASan-only, and GCC UBSan-only. Completion: all five existing suites plus any new suite run in every configuration. Dependencies: tasks 1–22.

24. Corruption and power-interruption simulations. Scope: expand fake-flash scenarios for positive, boundary, corruption, truncation, sequence-wrap, exact half-range ambiguity, unsupported-schema, both-slots-invalid, interrupted-erase, interrupted-program, CRC mismatch, length mismatch, malicious-field, eight-record payload length mismatch, forbidden persisted GPIO, unsupported enabled reserved channel, target-slot preservation, write/readback/reset failure, safe-point timeout, and flash-overlap cases. Tests: named regression cases for each category. Completion: every requirement test category is covered. Dependencies: tasks 13–23.

25. Regression verification. Scope: run the authoritative host configurations and ensure Features 001–004 tests still pass. Tests: GCC, Clang, GCC AddressSanitizer-only, GCC UndefinedBehaviorSanitizer-only host configurations, each running all registered suites. Completion: warning-clean host results. Dependencies: tasks 23–24.

26. Pico W Release build. Scope: build standard Release firmware with Pico SDK 2.3.0, Arm GNU Toolchain 15.2.Rel1, `PICO_BOARD=pico_w`, and picotool 2.3.0. Tests: `PICO_SDK_PATH=/absolute/path/to/pico-sdk-2.3.0 tools/verify_all.sh`. Completion: ELF, UF2, BIN, HEX, map, disassembly, metadata, reconstructed images, and deterministic size reports validated. Dependencies: task 25.

27. Firmware-size reporting. Scope: report application image end, persistent-region bounds, two slot sizes, flash/RAM usage, and static serialization buffers. Tests: verifier size output and map inspection. Completion: report proves no image/persistent overlap and no generated artifacts are committed. Dependencies: task 26.

28. Physical-validation preparation. Scope: prepare hardware test instructions for only valid, non-overlapping builds; document expected diagnostics for boot, save, interrupted write, reset, calibration persistence, and actual Release image/persistent bounds. Tests: build only; no physical pass claimed without owner report. Completion: `physical_validation.md` procedure is ready for owner execution and contains no intentionally overlapping image flashing. Dependencies: tasks 26–27.
