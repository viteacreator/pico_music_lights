# Feature 005 — Ordered Implementation Tasks

No task is implemented by this specification package. Every implementation task must leave the repository compilable, must not add Wi-Fi/web/JSON/OTA/USB configuration protocol scope, and must preserve Features 001–004 except where an approved task explicitly integrates loaded configuration.

1. Public configuration types and fixed limits. Scope: add `config/device_config.*` with fixed limits, schema-owned LED/effect/Idle/audio calibration value types, result enums, eight-channel persistent capacity (`kMaximumLedChannelCount = 8`), board-supported channel-count capability, physical metadata semantics (`length_mm == 0` unknown, density 0 unknown and any nonzero uint16_t informational), no persisted GPIO field, and static assertions separating persistent capacity from current board/effect runtime capacity. Likely files: new `include/config/`, `src/config/`, host CMake. Tests: compile-only and field-limit host tests. Completion: Pico and host builds compile. Dependencies: none.

2. Canonical Gyver audio-calibration ownership. Scope: make `AudioCalibrationConfig` the only canonical owner for Gyver VU/spectrum calibration, define adapters that overlay global calibration into runtime `StripEffectConfig` mirrors, and define normalization for active/draft reads. Likely files: new `config` adapter modules and host tests. Tests: canonical ownership, runtime overlay, read normalization, dirty/equality ignoring mirror fields, and contradictory mirror values rejected or normalized before persistence. Completion: no persisted API exposes per-channel contradictory Gyver calibration. Dependencies: task 1.

3. Factory defaults and physical metadata defaults. Scope: add factory construction for eight persistent channels: channels 0..5 enabled with current GP2–GP7 board mapping, 132/174/141/81/96/72 pixels, GRBW, unreversed, brightness 16, density 60, length 0 mm unknown, and Gyver VU defaults; channels 6..7 disabled with zero pixels, Effect Off, brightness 16, unreversed, unknown length, unknown density, and no stored GPIO. Tests: host assertions for every default field, current six-channel hardware defaults, reserved-channel defaults, known and unknown millimetre metadata, and global-only calibration defaults. Completion: defaults match requirements and no startup behavior changes. Dependencies: tasks 1–2.

4. Configuration validation. Scope: implement whole-config and preview-subset validation for fixed eight-channel capacity, current board-supported channels, unsupported channels disabled, enabled nonzero pixel counts, disabled-channel retained counts with runtime pixel count zero/no slice/no transmission adaptation, board/runtime total-pixel capability using `uint32_t`, brightness/order enums, optional metadata representation, absence of persisted GPIO, effects with calibration mirrors excluded, stable eight-bit Idle mask adapter with current reserved bits rejected, canonical audio floors, and overflow. Tests: positive, boundary, malicious-field, invalid enum/source/pixel/unsupported-channel/extra-payload-layout/Idle/audio/metadata cases, plus 300 accepted, 301 rejected, 500 rejected below total 800, total 800 accepted, total 801 rejected, disabled reserved retained count with runtime zero-count adaptation, and enabling a retained count rejected when it exceeds current limits. Completion: all invalid cases return typed diagnostics without side effects. Dependencies: tasks 1–3.

5. Draft, active, and persisted state management. Scope: add `ConfigService` state ownership using schema-owned effect and Idle config structs, a separate `has_persisted_record` state, factory-default comparison baseline, dirty tracking, reload/discard, normalized active/draft reads, and all-or-nothing publication stubs. Tests: empty-flash presence false with factory baseline/active/draft and dirty false, empty-storage Reload/discard, explicit unchanged-default Save eligibility, state transitions, and prevention of contradictory calibration state. Completion: record presence is never inferred from value equality and the service preserves current runtime until later integration tasks. Dependencies: task 4.

6. Explicit serialization and deserialization. Scope: add deterministic little-endian schema-1 codec with fixed buffers, exact stable enum ids, 978-byte payload, exactly eight 10-byte LED-channel records, exactly eight 106-byte effect records, one 30-byte Idle record, one 16-byte global audio record, no GPIO fields proved by known-byte and exact-payload-length tests, `uint16_t length_mm`, `uint16_t density_pixels_per_metre`, per-channel `uint16_t pixel_count`, board total-pixel capability outside the schema, duplicated Gyver calibration mirror fields excluded from effect records, global calibration serialized exactly once, canonical non-applicable effect defaults, and zero reserved bytes. Tests: round trip, golden header/LED/effect/Idle/audio bytes, exact complete payload length, known byte order, eight-record payload lengths, no serialized GPIO bytes, extra bytes and incompatible layouts rejected, serialization without duplicated calibration values, canonical calibration round trips, known/unknown millimetre metadata, truncation, length mismatch, malformed bool/enum, unknown enum ids, nonzero reserved bytes, integer-overflow safety, payload padding excluded from CRC, and no C++ padding/raw structure representation. Completion: no raw struct-memory persistence, no duplicated calibration payload, no persisted GPIO, exact schema-1 bytes are stable, and no schema dependence on current total-pixel capability. Dependencies: task 4.

7. CRC32. Scope: add standalone CRC-32/ISO-HDLC implementation with reflected polynomial `0xEDB88320`, initial `0xFFFFFFFF`, reflected input/output, and final XOR `0xFFFFFFFF`. Tests: ASCII `123456789` check vector `0xCBF43926`, incremental vs one-shot, empty payload, header CRC coverage mutation tests, payload CRC coverage mutation tests, payload padding excluded, and commit page excluded. Completion: usable by codec/record tests with exact coverage independent of C++ padding. Dependencies: none.

8. Slot format and slot inspection. Scope: define exact 64-byte header, 3840-byte data region, 4096-byte slot, final 256-byte dedicated commit page, magic bytes `50 4D 4C 43`, commit bytes `43 4D 54 31`, payload/header CRC checks, erased commit-page handling, and per-slot diagnostic summary. Tests: golden header bytes, exact slot data capacity, valid slot, erased commit page, fully valid commit page, bad magic, bad commit page, partial/malformed/inconsistent commit page, bad header CRC, bad payload CRC, bad length, unsupported schema, nonzero reserved bytes. Completion: host inspection classifies every case and never assumes four-byte flash programming. Dependencies: tasks 6–7.

9. Newest-valid-slot selection and sequence ambiguity. Scope: implement two-slot selection, ordinary half-range sequence comparison, duplicate equality handling, exact `0x80000000` ambiguity handling, diagnostics, and deterministic selected slot. Tests: one invalid/one valid, both invalid, both valid A newer, B newer, duplicate sequence selects A, wrap `0xFFFFFFFF -> 0`, exact half-range ambiguity selects A and emits `sequence_ambiguous`. Completion: selected source and fallback reason are deterministic. Dependencies: task 8.

10. Deterministic write-target selection. Scope: implement target choice without erasing the selected valid slot: other slot when one selected slot exists, non-selected slot when both are valid, slot B for duplicate/ambiguous A-selected cases, and slot A with initial sequence 0 when neither slot is valid. Tests: target selection, selected-slot preservation, initial save, alternating slots, sequence wrap next value, both invalid first write. Completion: old selected slot remains untouched before final verification. Dependencies: task 9.

11. Interrupted and corrupt write handling model. Scope: specify and implement the write transaction independent of hardware backend, with definite previous-slot authority before commit-page programming when one exists, explicit no-record behavior when it does not, and three best-effort inspection outcomes after commit programming is attempted: target valid and selected, target conclusively invalid, or `commit_state_unknown`; factory reset uses the same model. Tests: interrupted erase, interrupted payload programming, interruption throughout commit-page programming, commit completed with final-readback failure, retry inspection finding valid target, invalid target with and without a previous record, and unknown due to failed reads, reboot selection after each outcome, old-slot preservation, and unknown-case in-RAM last-verified/presence/dirty/diagnostic semantics. Completion: no post-commit failure path incorrectly claims old-slot physical authority, first-write failure preserves explicit no-record state, and unknown state never triggers automatic erase. Dependencies: tasks 8–10.

12. Flash backend abstraction. Scope: add read/erase/program/bounds interface with alignment, region descriptors, and operation counters for proving no pre-safe-point erase/program/commit operations while allowing harmless read-only slot inspection. Tests: fake backend rejects misalignment/out-of-range and records operations. Completion: storage code depends only on abstraction. Dependencies: task 11.

13. Host fake-flash backend. Scope: implement erase-state array, programmable 1-to-0 semantics, injected failures and interruption points. Tests: corruption and power-interruption simulations. Completion: all storage edge tests run without Pico SDK. Dependencies: task 12.

14. Device configuration store. Scope: combine codec, exact records, selection, target choice, fake backend writes, uncommitted verification, 256-byte commit-page programming, best-effort post-commit two-slot inspection, and last-verified/presence update for the eight-channel schema. Tests: save/load positive; empty-flash factory fallback with no persisted record; explicit unchanged-default first Save to slot A sequence 0; both slots invalid; unsupported schema; CRC/length mismatch; selected-slot preservation; alternating slots; valid/invalid/unknown post-commit outcomes and reboot selection; erased/valid commit pages; commit interruption; and reserved-channel retention. Completion: host store is deterministic when storage can be classified and reports bounded uncertainty when it cannot. Dependencies: tasks 6–13.

15. Persistent region layout checks. Scope: add compile-time constants and runtime validation hooks for flash size, sector alignment, slot placement, linker image end, and reserved areas, plus build/link-time reservation or size assertion. Tests: host runtime descriptor overlap/alignment cases and a build/link-time negative overlap verification that fails before a flashable artifact is produced. Completion: overlap is refused before slot access, the Pico build fails if the image would grow into the reserved region, and no intentionally overlapping image is flashed. Dependencies: task 12.

16. Pico SDK flash backend. Scope: implement RP2040 read/erase/program backend using SDK alignment, RAM-resident critical flash calls where required, and no real-time invocation. Tests: compile Pico Release; host remains unaffected. Completion: backend builds for Pico W and is not called from ISR/render paths. Dependencies: tasks 12 and 15.

17. Controlled runtime activation. Scope: publish previewable non-structural changes through explicit adapters from schema-owned config structs to EffectEngine and Idle Lighting at render-safe boundaries, adapt only current board-supported channels to the six-channel runtime LED/effect layers, keep channels 6 and 7 reserved/unimplemented, adapt disabled channels as runtime disabled with zero pixels/no slice/no transmission while retaining persisted counts, reject enabled unsupported channels, overlay canonical Gyver calibration into applicable runtime effect configs at the render boundary without adding an audio-processing publication path, and handle structural LED changes through two-phase reinitialization/restart boundary with existing-driver resource reuse. Tests: atomic success/failure, runtime overlay, board-supported-only publication, unsupported-channel rejection, disabled-channel retained-count adaptation, structural-not-mid-frame, PIO/DMA resource reuse, newly enabled board-supported channel single claim, claim-failure rollback, repeated enable/disable/save without resource leak, partial reinitialization failure, dirty tracking. Completion: invalid publication leaves active config unchanged. Dependencies: task 5.

18. Bounded safe-point acquisition. Scope: add compile-time bounded LED-frame and audio-safe-point deadlines before activation and before erase/program/commit, typed timeout diagnostics, state restoration, and operation-counter proof that no erase/program/commit was issued on timeout while read-only slot inspection remains allowed. Tests: permanently busy LED output, continuously pending audio work during Save/reset, timeout recovery, active/draft/persisted state unchanged, rendering/audio restored, wait-time diagnostics separated from flash critical-section time. Completion: Save aborts safely before erase/program on either timeout. Dependencies: tasks 12 and 17.

19. Controlled save integration. Scope: add the exact save coordinator through commit programming, then best-effort inspect both slots and classify target valid-selected, invalid, or unknown before updating last-verified state; permit explicit unchanged-default Save when presence is false. Tests: safe-point timeout, activation failure with no write, pre-commit failure, commit completed/final-readback failure, all three retry-inspection outcomes, old-slot preservation, unknown-case dirty/presence/diagnostics and Reload behavior, reboot selection, first Save to slot A sequence 0, and no erase/program/commit before both safe points. Completion: all failure phases match the design and no post-commit result overstates physical authority. Dependencies: tasks 14, 16, and 18.

20. Boot integration. Scope: normal startup independently inspects both slots, loads the newest valid supported config or initializes explicit no-record factory state before renderer enable, validates the eight-record payload against current board capability, publishes only board-supported channels, suppresses automatic diagnostic scenes in Release, and normalizes calibration mirrors. Tests: empty-flash `has_persisted_record=false`, factory baseline/active/draft, dirty false, fallback/no-record diagnostics, Reload/discard, plus reboot selection after valid/invalid/unknown prior commit outcomes and Pico build. Completion: empty storage is unambiguous and every boot derives physical authority from fresh slot inspection. Dependencies: tasks 14, 16, and 17.

21. Factory reset. Scope: explicit confirmation API, factory activation, reset through the same safe slot transaction and post-commit valid/invalid/unknown classification, and reset diagnostics. Tests: wrong confirmation rejected, confirmed reset restores defaults, pre-commit failure, target conclusively valid/invalid, unknown read failure, old-slot preservation, dirty and in-RAM last-verified semantics, and reboot selection. Completion: no accidental reset, no erase-both-slots behavior, and no unsupported authority claim after commit starts. Dependencies: tasks 19–20.

22. Bounded diagnostics. Scope: add fixed summary of boot source, persisted-record presence, factory fallback/no-record reason, slot states, target slot, duplicate/ambiguous sequence, `commit_state_unknown`, dirty flag, active-vs-last-verified status, validation error, save/reset status, safe-point wait durations, flash critical-section duration, dropped frames/audio interruption, schema, and flash bounds.
